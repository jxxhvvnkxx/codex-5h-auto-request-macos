# ⏱️ Codex 5시간 간격 자동 요청 — macOS

작은 Codex 요청을 자동으로 보내고, 성공 완료 후 5시간 간격으로 반복하도록 설정하는 설치 프롬프트입니다.

ChatGPT Plus 요금제로 ChatGPT Work와 Codex를 사용하는 Mac 사용자를 위한 **자동화 설치 프롬프트**입니다.

> 이 자동화는 서버 한도를 강제로 초기화하거나 늘리는 도구가 아닙니다. 자동 요청도 극소량의 구독 사용량을 소모합니다.

## 👤 대상 사용자

- macOS 또는 MacBook을 사용하고 있습니다.
- ChatGPT Plus를 구독하고 ChatGPT Work와 Codex를 사용합니다.
- Codex의 5시간 사용량 제한을 고려해, 한도 초기화 이후 작은 요청을 보내고 성공 완료 시각부터 5시간 간격으로 반복하도록 예약하고 싶습니다.
- 직접 스크립트를 작성하지 않고 AI의 도움으로 설치·검증·관리를 진행하고 싶습니다.

ChatGPT Work와 Codex는 사용량을 공유합니다. 이 자동화는 **ChatGPT 계정으로 로그인한 Codex CLI**를 사용하며, API 키 호출이나 일반 ChatGPT 예약 작업으로 대체하지 않습니다.

## 📦 이 저장소에는 무엇이 있나요?

이 저장소는 실행 프로그램이 아닌 **설치용 프롬프트**를 제공합니다.

AI가 프롬프트에 따라 사용자의 환경을 확인하고 다음을 구성하도록 요청합니다.

- macOS `launchd` 기반 자동 실행
- Codex CLI 설치 여부 및 ChatGPT 로그인 확인
- `OK`만 응답하도록 하는 작은 요청
- 성공 완료 시각을 기준으로 한 5시간 예약
- 오프라인 대기 및 중복 실행 방지
- 상태 확인, 안전한 로그 및 타임아웃 알림
- 백업, 롤백 및 완전 제거 방법

**설치 파일은 사용자 환경에 맞춰 생성되므로, AI가 보고한 설치 결과와 테스트 결과를 반드시 확인하세요.**

## 🚀 사용 방법

1. [macOS 설치 프롬프트](./prompt/masos-install-prompt.md)를 엽니다.
2. 프롬프트 전체를 복사합니다.
3. Mac 파일과 터미널에 접근할 수 있는 **ChatGPT Work 또는 Codex**에 붙여넣습니다.
4. 로그인 확인, 최초 실행 시각 선택 및 필요한 권한 승인을 진행합니다.
5. 설치 후 **현재 상태와 다음 예정 시각**을 확인합니다.

> Mac에 직접 접근할 수 없는 일반 웹 채팅에서는 붙여넣기만으로 설치되지 않습니다.  
> 이 경우 설치 파일과 직접 실행할 명령을 제공받아야 합니다.

### 🧠 설치할 때 어떤 모델을 선택하나요?

이 프롬프트의 설치·검증 작업에는 **GPT-6.1 Sol + 추론 수준 High**를 추천합니다. 계정의 ChatGPT Work 또는 Codex 모델 선택창에서 사용할 수 있을 때 선택하세요.

작은 요청 자체는 단순하지만, 자동화를 안전하게 구성하려면 다음 상황을 함께 검증해야 합니다.

- 잠자기·오프라인·재부팅 이후의 예약 처리
- 중복 실행 방지, 타임아웃 및 정확한 성공 판정
- 실제 Codex 요청 없이 테스트용 가짜 명령으로 실패 상황 검증

공식 안내는 복잡한 코딩 작업에 GPT-6.1 Sol을, 여러 단계와 예외 상황을 분석하는 작업에 높은 추론 수준을 권장합니다. 위 조합은 이를 바탕으로 한 이 프로젝트의 추천이며, 필수 조건은 아닙니다. High는 시간이 더 걸리고 사용량도 늘어날 수 있으므로, **사용량을 아끼려면 Medium으로 시작**해도 됩니다.

**설치용 모델과 자동 요청용 모델은 별개입니다.** 설치를 Sol로 진행하더라도, 스크립트의 작은 `OK` 요청은 설치 프롬프트에 지정된 `gpt-5.6-luna` · 추론 수준 `low`를 사용합니다. 설치 시 해당 모델과 옵션의 지원 여부를 확인하며, 사용할 수 없으면 임의로 다른 모델로 바꾸지 않습니다.

> 모델 선택만으로 오류 없는 설치가 보장되지는 않습니다. 설치 후 테스트 결과와 다음 예정 시각을 반드시 확인하세요.

### 🗓️ 최초 실행 시각은 반드시 확인합니다

붙여넣자마자 실제 Codex 요청을 보내지 않습니다. AI가 먼저 **현재 화면에 표시되는 5시간 한도 초기화 날짜·시각과 시간대**를 질문합니다.

- **활성화된 window가 있다면:** 확인한 초기화 시각보다 최소 30초 뒤로 첫 실행을 예약합니다.
- **활성화된 window가 없다고 확인했다면:** 사용자가 선택한 미래 시각으로 예약합니다.
- **한도 상태나 시각이 불명확하다면:** 설치 준비와 테스트까지만 진행하고 자동화는 활성화하지 않습니다.
- **설치 도중 예약 시각이 지났다면:** 즉시 실행하지 않고 현재 한도 상태와 새로운 미래 예약을 다시 확인합니다.

예를 들어 현재가 12:00이고 초기화 시각이 15:00이라면, 지금 설치해도 첫 실행은 **15:00:30 이후**로 예약합니다. 실제 요청은 네트워크 확인과 15초 안정화 때문에 조금 더 늦게 시작될 수 있습니다.

활성화 직전에는 설치 중 다른 기기 사용 등으로 표시된 한도 상태가 바뀌었는지도 확인합니다. 30초는 경계 오차를 줄이는 여유이며, 서버 초기화를 보장하는 값은 아닙니다.

> 복사·붙여넣기로 설치를 시작할 수 있지만, 최초 시각 확인과 필요한 권한 승인은 사용자가 진행해야 합니다. 설치 검증에는 실제 Codex 요청 대신 테스트용 가짜 명령을 사용합니다.

## ⚙️ 설치 후 동작 방식

### 정상 실행

**예정 시각 도달 → 네트워크 확인 → 15초 안정화 → 로그인 확인 → Codex 요청**

다음 두 조건을 모두 만족할 때만 성공으로 처리합니다.

- CLI 종료 코드가 `0`
- 최종 응답이 정확히 `OK`

성공하면 다음 예정 시각을 **요청 완료 시각 + 18,000초(5시간)** 로 저장합니다.

### 인터넷이 없을 때

Codex 요청을 보내지 않고 네트워크 복구를 기다립니다.

연결이 복구되면 15초간 안정화를 기다린 뒤 다시 확인하고, 요청을 한 번만 보냅니다. 연결 검사에는 작은 Apple HTTPS 성공 페이지를 사용하며, 모델 요청으로 인터넷 연결을 검사하지 않습니다.

### 결과가 불명확할 때

요청을 보낸 뒤 타임아웃이나 통신 중단이 발생하면, 서버가 이미 처리했을 가능성을 고려해 **짧은 간격으로 재요청하지 않습니다.**

- 종료 시각을 알면: 종료 시각부터 최소 5시간 대기
- 실행 중 재시작되어 종료 시각을 모르면: 복구 확인 시각부터 최소 5시간 대기

180초 제한으로 실행을 종료하면, 해당 사건에 대해 Mac 알림을 한 번 시도하고 상태와 로그에도 기록합니다.

### ⚠️ 로컬 예약과 서버 초기화 시각은 다를 수 있습니다

이 버전은 서버의 `resetsAt`을 조회하지 않고 **성공 완료 시각 + 5시간**으로 다음 요청을 예약합니다.

다른 기기에서의 사용이나 실행 지연 때문에 실제 서버 초기화 시각과 로컬 예약 시각이 달라질 수 있습니다. **요청 성공만으로 새로운 5시간 window가 시작됐다고 단정할 수는 없습니다.**

## 💤 잠자기·전원 꺼짐 상태에서는?

| Mac 상태                    | 동작                                          |
| --------------------------- | --------------------------------------------- |
| 깨어 있고 온라인            | 실행 조건을 확인한 뒤 요청                    |
| 인터넷 연결 없음            | 요청 없이 네트워크 복구 대기                  |
| 완전히 잠든 상태            | 실행을 보장하지 않음                          |
| 전원 꺼짐                   | 실행 불가                                     |
| 예정 시각 이후 깨어남       | 실행 조건이 충족되면 밀린 요청을 한 번만 실행 |
| macOS가 자체적으로 DarkWake | 실행 조건에 따라 동작할 수 있음               |

이 자동화는 **강제 깨우기, 자동 전원 켜기, 자동 로그인 또는 잠자기 방지 설정을 추가하지 않습니다.**

설치 후에는 ChatGPT나 Codex의 앱 창을 계속 열어 둘 필요는 없습니다. 다만 LaunchAgent가 실행 가능한 사용자 로그인 상태와 유효한 CLI 인증이 필요합니다.

## 🛠️ 상태 확인·중지·제거

설치 완료 후 AI에게 다음 정보를 받아 보관하세요.

- **상태 확인:** 현재 상태, 마지막 성공과 다음 예정 시각을 확인하는 명령
- **중지·재개:** 자동화를 멈추고 다시 활성화하는 명령
- **롤백:** 백업 경로와 이전 설정을 복원하는 방법
- **완전 제거:** 해당 LaunchAgent, 설치 파일, 상태와 로그를 제거하는 명령

문제를 공유할 때는 인증 파일이나 CLI 원문을 공개하지 말고, 개인정보를 제거한 상태 정보와 안전한 오류 코드만 공유하세요.
